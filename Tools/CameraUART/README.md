# K230 摄像头串口接收

## 接线和运行

- K230 实际串口 TX → STM32 PA3 / USART2_RX。
- STM32 PA2 / USART2_TX → K230 RX（只上传误差时可不接这一根）。
- 两端 GND 共地；使用 3.3V TTL 电平。
- 115200、8 数据位、无校验、1 停止位。
- 接收使用 DMA1 Channel6，蓝牙仍是 USART3 / PB10、PB11。
- 基础目标速度只由 `Core/Src/pid.c` 的全局变量 `Target_Speed` 决定。设 0 就保持零目标速度，设 30 才请求前进 30；摄像头不再另设基础速度。
- `Camera_TurnSign = 1` 位于 `Core/Src/camera_uart.c`，只控制视觉转向正负。
- 巡线开启且收到完整有效帧后，以 `Target_Speed` 为速度目标、`Target_Turn=error` 为转向输入；进入现有控制函数。
- 速度、直立、二次项转向计算以及 PWM/倾倒保护的原有参数没有修改。

## 接收协议和核验边界

根据亚博官方串口解析示例，接收标准 ASCII 彩色帧：

```text
$总字节数,1,x,y,w,h#
```

长度包含 `$` 和 `#`。第二字段为彩色识别例程编号 1。
用户给出的 `k230_8neighbor_midline.py` 将四个载荷定义为：

```text
x = error + 1000
y = 取点横坐标 = error + 320
w = 取点纵坐标（0..479）
h = 有效标志（0/1）
```

`Camera_Error=x-1000`，范围 -320..319；误差正数表示画面目标在右侧。
200 是普通误差数值，不是转 90 度的动作指令。

官方解析参考：https://github.com/YahboomTechnology/K230-Module/blob/master/main.ts

**未提供摄像头实际 `libs/YbProtocol.py`；以上是厂家标准格式假定。**
编译与 ARM 仿真可以验证 STM32 对该格式的行为，不能证明该摄像头库实际输出恰好相同。
烧录后先观察 OLED：`F` 应递增、`V` 应在识别正常时为 1，`E` 应与摄像头误差一致。
若只有 `B` 增加或一直 `F=0`，需要对照实际 `get_color_data()` 实现或串口原始报文，不能只改 PID。
OLED 7 行的 `F/B` 是成功解析帧数/坏帧数；第 6 行 `M=1` 是巡线模式，`M=0` 是手动模式。

## 停止和重新启用

- 有效标志 0、错包、DMA 溢出或超过 500 ms 没有完整有效帧时，送入速度环的有效速度及转向归零，直立控制继续；全局 `Target_Speed` 保留用户设置。
- 摄像头重新发来有效帧后，恢复用户设置的 `Target_Speed`，不会自动改成 30。
- 蓝牙上位机任何成功应用的 PID 参数包都会切到手动模式，摄像头只更新显示，不覆盖手动运动目标。这包括“发送全部参数”和方向/停止按钮。
- 从蓝牙串口发送文本 `CAM,1\n` 重新启用巡线；保留当前 `Target_Speed`，必须收到随后的一帧完整有效报文才会采用该速度。复位会回到巡线模式，并使用源码中的目标速度初值。
- 例如先发 PID 参数将目标速度设为 30，再发 `CAM,1\n`；若目标速度为 0，启用巡线也不会自动前进。
- 从蓝牙发送 `CAM,0\n` 暂停巡线并清零运动目标。命令返回 `OK\r\n`。
- 倾倒保护已锁存时，`CAM,1` 返回 `ERR,TILT`，仍需复位解除原有保护。
- 上位机尚未新增巡线开关；关闭上位机占用后可用串口助手发上述文本命令，或使用复位恢复默认巡线。

若左右转向反了，将 `Camera_TurnSign` 设为 -1 后重新编译烧录；保持原有陀螺仪反馈系数，单独核对其反馈方向。

## 软件验证

用 Keil 编译。`tests/test_camera_uart.py` 在 Unicorn 中执行编译后的实际 ARM 固件，
测试正负误差、分包/粘包、DMA 回绕和溢出、错包、超时/时钟回绕、蓝牙暂停及原有平衡优先混合。
不打开 COM 口，不下载固件，也不启动实际电机。
