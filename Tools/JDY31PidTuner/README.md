# JDY-31 PID调参上位机

本目录已有上位机源码 `Program.cs`。包含目标速度及转向环的可执行版本为 `JDY31PidTuner.ToggleMotion.exe`。
请使用 ToggleMotion 版本；速度 Kp 范围为 -20～100，转向指令范围为 -100～100。
固件已接入网表上的蓝牙接口：USART3，PB10 发送、PB11 接收，9600 8N1。

1. 将 `MDK-ARM/Blance car/Blance car.hex` 烧录到 STM32，给小车和 JDY-31 上电。首次调参先架空车轮。
2. 在Windows蓝牙设置中配对JDY-31。
3. 查看系统为JDY-31建立的“传出”COM端口。
4. 运行 `JDY31PidTuner.ToggleMotion.exe`，选择该COM口并连接。握手成功才会显示已连接。
5. “直立与速度”页在目标速度下方增加转向指令 Target_Turn，共7个参数；“转向环”页保留转向 Kp/Kd；每个参数右侧的步进量决定上下箭头每次变化多少。
6. 点击“发送全部参数”，日志收到 `OK` 表示单片机已经应用参数。修改输入框只保存到电脑，不会自动发给小车。
7. 上位机会在同目录的 `pid_settings.ini` 中自动保存每次调整，下次启动时自动载入。文件中已有历史调参值，发送前请核对，不能当作小车当前值。

串口参数为9600、8数据位、无校验、1停止位。发送协议：

```text
PING\n
```

单片机返回 `PONG\r\n`，用于连接握手及每10秒一次的心跳检测。

```text
PID,Vertical_Kp,Vertical_Kd,Velocity_Kp,Velocity_Ki,Med_Angle,Target_Speed,Turn_Kp,Turn_Kd,Target_Turn\n
```

单片机响应：

- `OK`：参数已应用。
- `ERR,FORMAT`：帧格式错误。
- `ERR,RANGE`：至少一个参数超出允许范围。
- `ERR,OVERFLOW`：接收帧过长。

参数范围与上位机一致：直立 Kp 为 -1000～1000，直立 Kd 为 -10～10，速度 Kp 为 -20～100，速度 Ki 为 -1～1，角度中值为 -45～45 度，目标速度为 -1000～1000 的整数。
转向 Kp 为 -200～200，转向 Kd 为 -5～5，转向指令为 -100～100 的整数。
九个参数全部校验通过后一起生效；速度 Kp/Ki 或目标速度改变时，在下一次控制周期清除速度积分。单独调整转向参数不会清除速度积分。格式错误、超范围、NaN/无穷值不会修改现有参数。

默认步进依次为：直立 Kp `10`、直立 Kd `0.01`、速度 Kp `0.01`、速度 Ki `0.001`、角度中值 `0.1`、目标速度 `1`。
`Target_Speed` 每次启动上位机均从 `0` 开始，不恢复上次的目标速度；其步长会保存。点击“发送全部参数”才会下发目标速度，点击该行“归零”后也需要发送才会生效。
固件复位后目标速度同样为 `0`；控制循环中原有的固定 `Target_Speed = 2` 赋值已移除。
目标速度沿用现有速度环的编码器计数单位，对应 `(-encoder_L + encoder_R) - Target_Speed`，不是米/秒；正负方向由实际电机和编码器接线决定。
新固件仍接受旧版5/6参数报文，并保留报文中省略的控制量。新版上位机需要配套新固件。

## 转向环

新增参数的初始值和步进：

| 参数 | 初始值 | 步进 |
| --- | --- | --- |
| Turn_Kp | 20 | 1 |
| Turn_Kd | 0 | 0.01 |
| Target_Turn | 0 | 1 |

`Target_Turn` 是左右转向指令，不是航向角或直接设定的角速度；每次启动上位机、复位单片机时都从0开始。转向 Kp/Kd 和步进会保存在电脑。
沿用原代码的计算公式：

```text
Turn_out = Turn_Kp * Target_Turn + Turn_Kd * gyroz
MOTOR1 = balance_pwm - Turn_out
MOTOR2 = balance_pwm + Turn_out
```

转向输出先限制在 ±1000 PWM；再按直立输出距离 ±5000 电机限幅的剩余空间限制转向，避免转向挤占平衡输出。OLED 第5行显示实际 `Turn` 输出和原始 `GZ`，用于观察方向与阻尼效果。

估算起调值为 `Turn_Kp=20`（可先在10～30内试调），`|Turn_Kd|` 可从0.1～0.3起调，先试0.2；程序默认 Kd=0，待确认反馈方向后再启用。这是基于当前PWM/陀螺仪单位的起调估计，没有代替实车辨识。
当前驱动配置为 ±2000°/s，原始陀螺仪灵敏度约16.4计数/(°/s)。例如10°/s对应GZ约164，Kd绝对值0.2产生约33 PWM阻尼；Kp=20、Target_Turn=5产生100 PWM转向指令项。[MPU-6050数据手册](https://invensense.tdk.com/wp-content/uploads/2015/02/MPU-6000-Datasheet.pdf)

调试顺序：先确认直立稳定、目标速度为0；以 Kd=0、Kp=20 检查小幅转向指令（如+3或+5）的方向，然后将指令归0。若正指令产生正GZ，应取负Kd（例如-0.2）；若正指令产生负GZ，应取正Kd（例如+0.2）。启用后反馈应阻碍旋转，而不是助推旋转；如左右抖动，先减小Kd绝对值并核对GZ噪声和符号。

新固件兼容5/6参数旧报文，省略的目标速度或转向参数保持原值；不完整的7/8参数报文会被拒绝。新版上位机发送9参数，必须烧录配套新固件，否则可能收到 `ERR,FORMAT`。

硬件接口（来自 `Netlist_Schematic1_2026-07-30.net`）：

| 接口针脚 | 连接 |
| --- | --- |
| 2 VCC | +5V；确认 JDY-31 底板支持此供电电压 |
| 3 GND | GND |
| 4 TXD | STM32 PB11 / USART3_RX |
| 5 RXD | STM32 PB10 / USART3_TX |
| 1、6 | 网表未连接 |

固件由 `Core/Src/bluetooth.c` 管理 USART3 和 DMA1_Channel3，采用循环 DMA 接收，在主循环解析和回复；平衡控制中断优先级高于蓝牙中断。
`Core/Src/pid_protocol.c` 负责协议和范围校验。蓝牙驱动为手工接入，当前 `.ioc` 未配置 USART3，使用 CubeMX 重新生成后需要保留这些模块和主循环调用。

如果连接提示 PING 无响应，检查：是否烧录了新固件、是否选择传出 COM 口、JDY-31 的实际串口波特率是否为9600，以及 STM32 是否已正常启动。
蓝牙现已在 OLED/MPU 初始化之前启动；MPU 初始化返回失败后仍处理蓝牙命令，但保持电机 PWM 未启动，平衡控制中断也不会执行。OLED 显示 `MPU ERR` 时应先排查传感器，再运行小车。

注意：参数发送成功后只保存在RAM中，单片机复位后恢复源码默认值。

## 倾倒停机保护

前后倾角 `pitch` 偏离机械中值 `Med_Angle` **超过 30°** 时，下位机在该次控制计算中将两路电机 PWM 置零，并锁定停机。恰好偏离 30° 不触发，前倾、后倾均检查；判断不使用速度环修正后的目标角度。

停机时清除速度积分、速度滤波历史、目标速度及转向指令，OLED 第6行显示 `TILT STOP:RESET`。扶正车身或重新发送上位机参数均不会解除锁定；锁定后仍可调整增益，但运动指令保持为0。扶正后需复位单片机才能恢复控制；复位时仍超过阈值会再次停机。

## 运动控制页

设置固定速度和固定转向值后，四个方向按互斥开关工作：第一次点击执行对应方向，再点同一个方向则速度和转向都归零。切换方向时清除上一指令；例如前进后点右拐，Target_Speed 立即归零，只保留右拐的 Target_Turn。选中方向按钮会高亮。方向按钮立即发送当前全部参数；通信忙时只保留最新目标，停止会覆盖等待中的运动目标。收到 OK 才代表下位机确认。

固定速度和固定转向值独立保存，不改变参数页的步进设置。两项固定值初始为0，使用前可自行调整；重开软件恢复固定值，但运动目标仍归零。方向不符时使用前后反向或左右反向选项；反向选项会保存。停止将两项运动指令归零并保持平衡控制。断开连接时清除待发送指令；重新启动软件时运动目标仍从零开始。停止命令需要通信正常才能送达。
